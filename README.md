# مغسلتك — v2

التاريخ: 2026-10-11. هذه النسخة تضع هيكل النظام فقط.

## المشاريع

- `admin-web/`: واجهة الإدارة للطلبات والأسعار والخدمات والمندوبين والتقارير.
- `kiosk-web/`: واجهة الكشك لتسجيل القطع والخدمات، مع خيار المستعجل داخل اختيار القطعة والخدمة، ثم تأكيد العامل للاستلام.
- `customer-web/`: واجهة الجوال لإنشاء طلب الاستلام من المنزل وتتبع حالته.
- `shared/`: مخطط البيانات، حالات الطلب، والانتقالات المسموحة بينها.

كل واجهة مشروع مستقل بملفاته الخاصة. لا تتصل الواجهات بقاعدة البيانات مباشرة. عند بناء التشغيل الفعلي، تتواصل الواجهات الثلاث عبر واجهة برمجة تطبيقات (API) مشتركة، ويتولى الخادم وحده قراءة قاعدة البيانات وكتابتها. يستخدم الخادم `shared/schema.sql` و`shared/order-statuses.json` و`shared/order-status-transitions.json` مرجعًا واحدًا، ويطبق الصلاحيات بحيث لا تصل واجهة العميل إلى وظائف الإدارة أو العامل.

يغطي المخطط طريقتي استلام الطلب بعد التجهيز: الاستلام من المغسلة أو التوصيل للمنزل. يتطلب التوصيل عنوانًا وموعدًا، بينما لا تُحفظ هذه الحقول للاستلام من المغسلة. كما يسجل العامل ووقت تأكيد استلام الملابس.

يمثل `custom_item_name` خيار «قطعة أخرى»، ويظل `unit_price` فارغًا حتى تحدد المغسلة السعر. يوجد خيار المستعجل في بند الطلب نفسه، ويرتبط البند بمصدر طلبه لمنع المستعجل ما لم يكن المصدر `kiosk`.

انتقالات الحالة المسموحة تسير بالترتيب فقط:

`جديد` → `بانتظار الاستلام` → `تم الاستلام` → `تحت المعالجة` → `جاهز` → `بالتوصيل` → `تم التسليم`.

لم يُنشأ خادم أو اتصال فعلي بقاعدة البيانات في هذه المرحلة. اختيار محرك قاعدة البيانات، آلية تسجيل الدخول، قواعد التسعير، ورسوم المستعجل تُحدد لاحقًا.
